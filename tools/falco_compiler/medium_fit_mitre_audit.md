# Step 4 medium-fit direct MITRE audit

This is the targeted 14-row audit requested after the first step-4 checkpoint. Each finding was checked against the linked official MITRE ATT&CK technique page.

| Rule | Technique reviewed | Direct MITRE finding | Outcome | Limitation |
|---|---|---|---|---|
| Disallowed K8s User | [T1078](https://attack.mitre.org/techniques/T1078/) | T1078 covers abuse of existing valid credentials and explicitly includes Containers; its current detection guidance includes anomalous container service-account or kubeconfig use. | retain_candidate | The Falco event establishes use by an unexpected authenticated identity, but operational context is still required to distinguish compromise from an incomplete allowlist. |
| Create HostIPC Pod | [T1610](https://attack.mitre.org/techniques/T1610/) | T1610 covers deploying a container, including containers configured without normal isolation or defensive restrictions. | retain_candidate | The event proves the risky deployment, not a subsequent host escape. |
| Anonymous Request Allowed | [T1133](https://attack.mitre.org/techniques/T1133/) | T1133 explicitly includes access through an exposed Kubernetes API that does not require authentication. | retain_candidate | Health, live, and readiness endpoints are excluded by the Falco condition. |
| port-forward | [T1609](https://attack.mitre.org/techniques/T1609/) | T1609 is scoped to executing commands inside containers through administration services; port-forward creates a network tunnel without command execution. | move_to_needs_review | No current ATT&CK Containers technique cleanly covers this event alone. |
| Pod Created in Kube Namespace | [T1036.005](https://attack.mitre.org/techniques/T1036/005/) | T1036.005 explicitly describes creating a resource in a trusted namespace or matching a container pod or cluster naming convention. | retain_candidate | The Falco allowlist exclusion is necessary because legitimate system pods also use these namespaces. |
| Service Account Created in Kube Namespace | [T1136](https://attack.mitre.org/techniques/T1136/) | T1136 covers creation of an account for persistent access and lists Containers as a supported platform. | retain_candidate | The event proves account creation; malicious persistence intent remains contextual. |
| K8s Deployment Deleted | [T1485](https://attack.mitre.org/techniques/T1485/) | T1485 includes deletion of cloud infrastructure crucial to operations to damage availability and supports Containers. | retain_candidate | A single successful deployment deletion is a medium-confidence signal; intent and operational criticality remain contextual. |
| K8s ConfigMap Deleted | [T1485](https://attack.mitre.org/techniques/T1485/) | T1485 covers destruction of data or files to interrupt availability and supports Containers. | retain_candidate | The successful deletion destroys stored configuration data, but impact and adversarial intent remain contextual. |
| K8s Namespace Deleted | [T1485](https://attack.mitre.org/techniques/T1485/) | T1485 includes deletion of cloud infrastructure crucial to operations and supports Containers. | retain_candidate | Namespace deletion can cascade across resources; whether the affected namespace is operationally critical remains contextual. |
| K8s Serviceaccount Created | [T1136](https://attack.mitre.org/techniques/T1136/) | T1136 covers creation of accounts for persistent access and supports Containers. | retain_candidate | The generic creation event requires context to distinguish adversary persistence from normal administration. |
| K8s Secret Deleted | [T1485](https://attack.mitre.org/techniques/T1485/) | T1485 covers destruction of stored data to interrupt services and supports Containers. | retain_candidate | The rule excludes service-account tokens and kube-system; impact and adversarial intent remain contextual. |
| ECS Service Created | [T1610](https://attack.mitre.org/techniques/T1610/) | T1610 covers deploying containers through container management APIs; an ECS service is the orchestration object that deploys and maintains ECS tasks. | retain_candidate | The event is retained at medium confidence because the compiled Falco predicate does not inspect desired task count or image content. |
| Update Lambda Function Code | [T1578.005](https://attack.mitre.org/techniques/T1578/005/) | T1578.005 covers infrastructure-level settings such as quotas, subscriptions, tenant-wide policies, and deployment regions, not application code in an existing function. | move_to_needs_review | T1648 does not cleanly establish this update event as serverless execution without execution context. |
| Update Lambda Function Configuration | [T1578.005](https://attack.mitre.org/techniques/T1578/005/) | T1578.005 covers infrastructure-level compute settings, not an existing Lambda function's application or runtime configuration. | move_to_needs_review | No current ATT&CK technique cleanly covers the generic configuration update event by itself. |
